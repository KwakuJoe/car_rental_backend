CAR RENTAL BACKEND — BOOKINGS MODULE REFERENCE (M1.7 numbering, M3.4 availability,
M3.5 bookings, M3.6 cancellation policy) - Phase 3 slice 2
==================================================================================
Runnable examples: http/bookings.http.
Permissions: bookings.view (list, detail, history, availability, cancellation preview),
bookings.create (POST /quotes and POST /bookings), bookings.update (confirm, notes),
bookings.cancel (cancel, no-show), bookings.override (blacklisted customer, under-age

Roles: manager all five; front desk view/create/update/cancel; fleet + accountant view.
NOTE: POST /admin/quotes moved from pricing.view to bookings.create.

NUMBERING (M1.7) - NumberingService.next('booking', trx)
WYK-2026-00123: businesses.document_prefix (default WYK; editable on PUT /admin/business as
documentPrefix, 2-6 letters or digits - new references only) + year (business time zone) +
5-digit number restarting each year. document_sequences (type, year, next_value) row,

AVAILABILITY (M3.4)
GET /admin/availability?from=&to=&categoryId=&driveType=&transmission=&fuelType=&search=
  &page=&limit= (paginated, default 12, { data, meta })
  from/to ISO in the business time zone (default: now, for one day). Cars free for the
  whole period PLUS the turnaround buffer (booking.turnaround_buffer_minutes), active and
  not archived; driveType=self_drive leaves out chauffeur-only categories; search matches
  make, model or plate (spaces ignored). Returns id, name, registrationNo, transmission,
  fuelType, seats, colour, coverUrl, category. Only a hint -
  the booking itself is protected by the car_allocations exclusion constraint.

BOOKINGS (bookings, booking_extras)
Columns: reference, branch/customer/car/category, source (walk_in | phone | whatsapp |
website | corporate - staff can't pick website), drive_type, status, pickup_at, return_at,
delivery/collection zone + address, out_of_town, driver_nights_away, destination,
protection_plan_id, hold_expires_at, price_snapshot (the full Quote), subtotal (before
discount), discount_amount + reason, tax, total, deposit, reservation_fee, paid, balance
(payments keep these in sync - Phase 5), override_reason/by, confirmed/cancelled/no_show
fields, cancellation_fee_amount, notes. booking_extras snapshot name + price as booked.

Status machine (BookingService.assertTransition):
  pending -> confirmed | cancelled | expired | no_show
  confirmed -> on_rent (Phase 4) | cancelled | no_show
  on_rent -> returned -> closed (Phase 4/5); cancelled / no_show / expired are final.
  draft exists for later (online checkout); staff bookings start pending or confirmed.

POST /admin/bookings  { customerId, carId, pickupAt, returnAt, driveType, source,
  outOfTown?, driverNightsAway?, extras?[{extraId, quantity}], protectionPlanId? (omit =
  default, null = none), deliveryZoneId?, deliveryAddress?, collectionZoneId?,
  collectionAddress?, destination?, notes?, discountAmount? (pesewas off the rental),
  discountReason?, overrideReason?, confirm? }
  - Prices ONLY through PricingService.quote() (discount = a negative "discount" line,
    taxed as rental); the quote is frozen in price_snapshot.
  - confirm=true -> confirmed (allocation source 'booking'); otherwise pending, held for
    booking.staff_hold_hours (allocation source 'hold'), then bookings:expire-holds
    expires it and frees the car.
  - Refused (422, field named): pickup more than 1h in the past; archived customer;
    blacklist block; self-drive driver under the minimum age (category override or
    booking.min_driver_age); discount without a reason or above
    booking.staff_discount_limit_percent of the rental; min/max rental days; pickup or
    return on a closure day or after hours when after-hours handovers aren't offered;
    any QuoteError. The three manager cases pass with bookings.override + overrideReason
    (audited in metadata.overrides).
  - 409 E_CAR_UNAVAILABLE when the car is taken (checked up front, and the exclusion
    constraint catches races - tests/functional/bookings.spec.ts runs five at once).
  - Warnings (201, data.warnings): blacklist warn, no date of birth, no licence on file,
    licence expiring before the return or held less than booking.min_licence_years, car
    roadworthy/insurance expiring before the return, other quote warnings. Lead time is
    ignored for staff.
GET  /admin/bookings  ?search (reference, customer name or phone) &status &upcoming=true
  (held / confirmed / on rent, not yet due back) &customerId
  &carId &source &driveType &dateFrom &dateTo (pickup date) &sortBy=pickupAt|createdAt
GET  /admin/bookings/:id   booking + quote (the snapshot); car includes coverUrl
PUT  /admin/bookings/:id   { destination?, notes? } - dates, car and extras change via
  modifications (M3.8, slice 4)
POST /admin/bookings/:id/confirm
GET  /admin/bookings/:id/cancellation-preview  -> CancellationService.evaluate
POST /admin/bookings/:id/cancel  { reason }  - frees the car, stores the policy fee
POST /admin/bookings/:id/no-show - only cancellation.no_show_after_hours after pickup;
  frees the car, late charge applies
GET  /admin/bookings/:id/history - the booking's audit entries, oldest first
Audit actions: booking.created, booking.confirmed, booking.updated, booking.cancelled,
booking.no_show, booking.expired (system).

CANCELLATION POLICY (M3.6) - CancellationService.evaluate(booking, { noShow? })
Settings (group "Cancellation & no-show"): cancellation.full_refund_hours (72),
cancellation.fee_only_hours (24), cancellation.late_charge_days (1),
cancellation.no_show_after_hours (2).
  >= full_refund_hours before pickup  free
  >= fee_only_hours                   reservation fee kept
  later, or a no-show                 reservation fee + late_charge_days x average day
Fee capped at the total; refundable = paid - fee (never negative). Refunds: Phase 5.

CHANGES (M3.8) - booking_modifications (type, before, after, price_difference_amount,
quote, reason, created_by); ModificationService.plan / apply (bookings.update)
POST /admin/bookings/:id/modifications/preview  -> the plan, nothing saved
POST /admin/bookings/:id/modifications          -> applies it
  { type: extend, returnAt }            pending/confirmed/on_rent. The extra time is priced
      at TODAY's rates (quote from the old return to the new one, extension mode: no
      pickup fees, lead time or minimum length) and ADDED to the agreed total.
  { type: change_dates, pickupAt, returnAt }  pending/confirmed. The whole booking is
      re-priced (new snapshot, discount kept, extras re-priced); difference = new - old.
  { type: swap_car, carId, charge: none|difference, reason }  pending/confirmed.
      none = the agreed price stays (e.g. our car broke down); difference = re-priced.
  { type: early_return, returnAt? (default now) }  on_rent only (Phase 4). Refund per
      setting booking.early_return_refund: none (default) | unused_days.
  The car allocation (and the driver's) moves in the same transaction: a clash is 409.
  Same refusals as booking (closure days, after hours, min/max days). A driver's licence
  must still cover the new return. Audit: booking.modified (metadata type, difference).

DRIVERS (M3.9) - drivers (user_id nullable, full_name, phone E.164, licence_no,
licence_class, licence_expires_on, status active|on_leave|inactive, daily_rate_amount =
cost to the business, notes); driver_allocations with an exclusion constraint like cars.
GET  /admin/drivers ?search &status &availableFrom &availableTo &excludeBookingId (drivers.view)
POST /admin/drivers, PUT /admin/drivers/:id (drivers.manage) - never deleted, set inactive
PUT  /admin/bookings/:id/driver { driverId | null } (bookings.update) - with-driver bookings
  only; driver active with a licence valid through the return; 409 E_DRIVER_UNAVAILABLE
  when they drive another booking then. Cancel / no-show / expiry free the driver too.
  Today board: a with-driver pickup without a driver is "not ready".
Roles: manager drivers.view + manage; front desk and fleet drivers.view.

CALENDAR (M3.7) - GET /admin/calendar?from=&to=&categoryId=&search=&page=&limit=
(bookings.view). Days YYYY-MM-DD in the business time zone (default today + 13 days, at
most ~2 months). One row per car (paginated, default 20; archived and retired cars left
out, cars with nothing booked still listed) with items = active allocations overlapping
the period: { source, startsAt, endsAt, endsAtWithBuffer (cleaning time), reason,
booking: { id, reference, status, driveType, customerName } | null (a block) }.
