CAR RENTAL BACKEND — VEHICLE HANDOVER (Phase 4: M4.1 check-out, M4.2 signatures)
==================================================================================
Permissions: handover.checkout (check-out), handover.checkin (check-in, slice 2).
Roles: manager, front desk and fleet both.

DECIDED with the owner (2026-10-27):
- Money: until Phase 5 records payments, staff tick "balance and deposit collected"
  (inspection.payment_confirmed + payment_confirmed_by). Phase 5 replaces the tick.
- Terms: a versioned text (terms_versions), seeded with a clearly-marked DRAFT the owner
  replaces before go-live (Settings). Every signature records the version + a hash.
- Photos: optional. Setting handover.require_photos (off) makes six angles required:
  front, rear, left, right, odometer, fuel_gauge.

TABLES
inspections (booking_id + type unique: check_out | check_in; draft -> completed):
  odometer_km, fuel_level (eighths 0-8), checklist jsonb [{itemId, name, result ok |
  missing | damaged, note}], exterior clean|dirty, interior clean|dirty|smoking, notes,
  payment_confirmed(+_by), terms_version_id, agreement_hash (SHA-256 of terms body +
  version + booking reference/dates/car/total + odometer/fuel), signature_file_id
  (private file, purpose signature), signed_name, signed_at, signer_ip, signer_device,
  inspected_by, completed_at.
inspection_photos (angle, file_id) - purpose inspection_photo (public URL: car evidence).
car_damages - the CAR's damage register: zone (DAMAGE_ZONES of the top-view diagram),
  x/y (0-100 % within the diagram), type, severity, note, photo, reported_inspection_id,
  repaired_at (Phase 8). Open damage shows at every handover as preexisting.
checklist_items (name, sort_order, active) - seeded defaults, edited in Settings.
terms_versions (version, body) - never edited; a change is a new version.
bookings.actual_pickup_at / actual_return_at.

CHECK-OUT (CheckOutService)
GET  /admin/bookings/:id/check-out   creates the draft on first open; returns
  { inspection, requirements[{code,label,ok,message}], ready, damages, car
  {currentOdometerKm}, terms {id, version, body}, requirePhotos }
PUT  /admin/bookings/:id/check-out   save the draft { odometerKm, fuelLevel, checklist,
  exterior, interior, notes, photos[{angle, fileId}] (replaces), paymentConfirmed }
POST /admin/bookings/:id/check-out/damages            mark damage on the diagram
DELETE /admin/bookings/:id/check-out/damages/:damageId  only damage from this handover
POST /admin/bookings/:id/check-out/complete { signatureFileId, signedName }
  Refused (422, code = the failing requirement) unless ALL pass:
  confirmed; customer not blocked (unless the booking has a manager override); ID (+
  licence for self-drive) verified when booking.require_verified_customer_for_checkout;
  with-driver bookings have a driver; car active; roadworthy + insurance valid today;
  odometer >= the car's last reading; fuel recorded; photos (if required); money ticked.
  Then: inspection completed with the signature, terms version and hash; booking ->
  on_rent + actual_pickup_at; car odometer updated (odometer_logs source check_out);
  audit booking.checked_out. A completed inspection can't change (422).

Collected early: completing check-out before the booked pickup moves the car (and
driver) hold to start NOW; a clash with the previous booking is a 409.

CHECK-IN (CheckInService, M4.3) - same screen shape, handover.checkin
GET/PUT /admin/bookings/:id/check-in, POST/DELETE .../check-in/damages
  The draft starts from the check-out checklist. The screen adds
  comparison { checkOut, checkIn, kmDriven, includedKm, lateMinutes, damageCap, proposed[] }
  and the saved charges. Requirements: on rent, odometer >= the check-out reading, fuel.
Proposed charges (only ACTIVE fees from Pricing -> Fees; nothing is saved until complete):
  excess_km     km over snapshot.mileage.includedKm x (rate's excess price or fee excess_km)
  fuel          eighths short x tank (car fuel_capacity_l, else handover.default_tank_litres)
                -> litres x fee fuel_per_litre; plus refuel_service
  late_hours    after return + grace: hours x late_return_hour while cheaper than a day,
  late_days     else whole days x the booking's average daily price
  damage        each damage marked at check-in - staff enter the amount (not taxed)
  missing_item  items OK at check-out, missing now (lost_key / lost_document fees, else
                staff enter the amount)
  cleaning / smoking   dirtier than at check-out
POST /admin/bookings/:id/check-in/complete { charges[{code, label, quantity, unitAmount,
  amount, taxable, waived, waiveReason}], overrideReason? }
  - a waived line needs a reason; waivers above handover.waiver_limit (GHS 200) and damage
    above the protection plan's excess (negligence) need bookings.override + reason
  - accepted lines -> booking_charges (+ taxes as "fees"), added to the booking total and
    balance; waived lines are kept with their reason; zero lines aren't saved
  - booking -> returned + actual_return_at; car odometer (log source check_in); back early
    -> the car is free after its cleaning time from now (never before the hold's start)
  - audit booking.checked_in (charges, waived, override reason)

TERMS & CHECKLIST
GET /admin/terms, GET /admin/checklist-items (bookings.view)
POST /admin/terms { body } (settings.manage) - a new version (same text = no-op)
PUT /admin/checklist-items { items[{id?, name, active}] } (settings.manage) - replaces
  the list in order; removed items are switched off (old inspections still name them).

PDFS (M4.4) - HandoverPdfService (PDFKit: pure JS, no headless browser on the server)
GET /admin/bookings/:id/agreement.pdf       after check-out (422 before)
GET /admin/bookings/:id/check-in-report.pdf after check-in (422 before)
(bookings.view, inline, filename <reference>-agreement.pdf / -return.pdf)
Built on request from records that don't change after signing: the price snapshot as
booked (+ "Changes after booking" from booking_modifications), the check-out inspection,
the car's damage as at signing, the terms version signed, the signature image (private
file fetched with a 60 s signed URL; "(signature on file)" if unreachable), signer IP and
the agreement fingerprint. ID / licence numbers masked. A4, page numbers.
The return report: readings out vs back, km driven, checklist issues, new damage with the
diagram, charges (accepted + waived with reasons), total / paid / balance.
House style: app/services/pdf/pdf_document.ts (PdfDocument), which invoices and receipts
reuse in Phase 5. Manrope (@fontsource/manrope .woff; fontkit crashes subsetting WOFF2),
brand bar on top, letterhead (logo slot, monogram until a logo is uploaded), summary
tiles, bordered fact cards, charges table with highlighted total and chips, fuel gauge,
terms in two balanced columns (paragraphs never split; carries over pages), business
name watermark at 4.5% drawn last (on top of cards), footer "REF · Page X of Y".
Agreement: 2 pages typical. Return report: 1 page (charges before the damage card).
Business logo upload: deferred, owner to decide; pass it as letterhead.logo (Buffer).
